# CarPlay 0.2.35 — 低延迟音频与有线播放

主应用版本：`0.2.35`，Android `versionCode=42`。基于 `main` 的
`e2cc3c6d203e2333a9739dc7c7ed858ec5c18ffa` 开发，延续 0.2.34 的协议和时钟修复。

## 配置与运行行为

| 项目 | 本版行为 | 数值的含义 |
| --- | --- | --- |
| 无线音乐 | 新增 150ms，作为未保存设置时的默认值；300/500/1000ms 仍可选择 | PCM 启动预缓冲目标 |
| 有线音乐 | 未保存 USB 独立设置时默认 100ms，不再继承旧无线缓冲 | PCM 启动预缓冲目标 |
| 增强缓冲音乐 | 无线 150ms、USB 100ms 的输出启动预算；网络预取库存继续保留 | 接收端重启/切歌的预缓冲目标 |
| 有线语音、导航 | 按采样率计算时长，避免固定字节下限造成几百毫秒库存 | 尊重平台最小音轨容量的低延迟计划 |
| 有线平滑视频 | 30fps 初值 100ms、60fps 初值 90ms，动态上限 100ms | 从本机接收帧起算的主动显示调度等待 |

以前明确保存的独立音乐缓冲选项仍然有效。升级后若无线仍显示 1000ms，可在
**设置 → 音频 → 音乐缓冲**选择 150ms；USB 选择 100ms。保存后提示重连，
不会直接打断当前音乐。较大缓冲仍可用于无线信号不稳定的场景。

## 延迟修复

- 短音乐缓冲不再附加原来的 200ms PCM 容量余量；短尾音不再固定等待至少 500ms。
- 停止旧音轨时立即暂停并清空未播放 PCM，随后释放解码器，减少旧歌残响。
- 实时 UDP 音频关闭增加回调结束屏障，关闭后不再把已解密的旧音频送回播放器；
  TEARDOWN 先等待旧接收回调结束，再停止对应音轨。
- 增强缓冲音乐使用可观测的播放头判断哪些帧已经听到，避免慢启动或暂停时
  仅按墙钟误删尚未播放的音乐。
- 增强音乐的解码队列满时保留当前帧并重试，不因短缓冲丢掉预取音乐；连续投喂
  在启动测量期间发生超过 100ms 的间断时重新测量，避免短暂断流被误学成播放时钟偏差。
- 有线视频把时钟校正和自适应平滑合并计入同一个 100ms 软件预算，避免两者叠加；
  解码超时的帧立即显示，不通过任意丢参考帧制造低延迟。
- USB/TCP 正常转发未发现固定凑包等待。读写故障超时继续保留，其数值不等于正常转发延迟。

## 图标与版本管理

启动器和应用内标记统一为绿色 CarPlay 圆形播放图标，提供普通、圆形、自适应和
Android 13 主题图标资源。协议名称、包名、中文与 Steam 标识继续沿用。
音乐缓冲选择项可随大字体和较长翻译自动增高，完整显示数值及默认标识。

`scripts/version.py bump` 同时递增可见版本与 Android 安装版本。CI 在生产源码、
资源或依赖变更时比较 PR 基准/主线前一提交，阻止漏升版本；同一待合并更新的修复
提交可以共用 0.2.35。独立 AAOS 包同步更新为 `1.2.2` / `1202`。

## 验证范围

本版需要执行仓库规定的完整 Gradle 单元测试、Lint 和三个 Debug 应用构建。
回归包含低容量音轨、切歌/停止并发、缓冲音乐背压、播放头停滞与回绕、设置迁移、
有线视频时钟偏移和 30/60fps 调度，结果以本次交付记录与 CI 为准。

100ms / 150ms **不是实车端到端测量值**。手机准备下一首歌曲、Wi-Fi 间隙、USB、
Android 音频 HAL、功放 DSP、硬件解码与显示刷新都在总延迟中；平台报告的音轨
最小缓冲必须得到尊重。无线收包间隙超过所选缓冲时仍可能断音。
增强音乐还在实际启动门槛之外保留 20ms 投喂轮询和一个 AAC 帧的余量，网络预取
库存与渲染器提前投喂量也不是实测切歌时间。日志会分别报告请求缓冲、实际音轨
容量、软件启动门槛和平台启动门槛，便于后续用车机实测校准。

## 安装与实车检查

正式源码仍不包含认证或签名材料。独立车测包使用用户已有的运行材料和原签名，
与 0.2.34 测试包保持 `com.solhk.carplay.hudtest` 包名；源码版 CI APK 的用途不同，
不要把它当作已准备好的独立连接包。构建方法见 [BUILD.md](BUILD.md)。

停车后使用同一手机、同一歌曲依次比较旧版和新版：

1. 确认关于页为 0.2.35，图标正确；选择无线 150ms 或 USB 100ms 后重连。
2. 连续切歌、暂停/恢复，检查是否有旧歌残响、重复片段、完全不出声。
3. 播放音乐并触发导航播报、Siri、通话与恢复，检查声音路由和连续性。
4. 使用 30fps/60fps 地图操作观察显示响应；检查拔线重连后的恢复。
5. 对比按键时间和实际声学输出，记录中位值、P95 和断音次数；仅凭设置显示值
   不能把 150ms 切歌或 100ms 有线总延迟标记为通过。
