# CarPlay 0.2.34 测试版

同步 DiPlay 主线截至 2026-10-24 的接收端功能与修复，基准范围为 `6d3b8a8ce927cb4b115b8c3881f17619433e93b1` → `9d89633035d1add5b044ba3de5e57dd078bf2511`。保留 SOLHK 的主页、音乐页、应用包名、连接标识与设置键；上游网站和发布工作流未移植。上游改动详见 [DiPlay 后续更新记录](RELEASE-NOTES-NEXT.md)。

## 音乐断续的证据与处理

用户提供的 DiLink 5.0 / Android 12 无线诊断中，音乐使用 AAC-LC / 48 kHz，播放缓冲容量为 500 ms，启动缓冲为 300 ms。导出的音乐接收记录包含最长约 759 ms 的接收等待、282 个缺失 UDP 序号；音乐输出记录累计 13 次 underrun，12 次重新缓冲。没有记录到音乐解码丢弃或 AudioTrack 写入错误。这些计数仅代表此次日志覆盖的会话，并非新的真机测试。

- 同步上游 #993、#1070、#1080 的音乐时钟修复，按时间平均计算缓冲水平、在每次开播后测量实际工作水位，并计入阻塞写入期间已经到达的音频，避免错误加速播放耗尽缓冲。
- **无线新安装**默认使用 1000 ms 音乐缓冲，代价是播放/暂停反馈可能稍迟。USB 仍默认 300 ms。已有保存值不被覆盖；若恢复旧设置，请在“设置 → 音频 → 音乐缓冲”选择 1000 ms，并重新连接。
- 当 1000 ms 缓冲尚未填满时，收尾开播等待也至少为 1000 ms，避免在 500～760 ms 无线停顿期间提前绕过长缓冲。真正的短尾音仍会在有限等待后播放。
- 通话、Siri、导航的原有短缓冲保留。没有自动切换音频通道、音频焦点或实验性 TCP 音乐模式。

缓冲和时钟修复不能重建已经丢失的 UDP 音频。若新包仍在同一路段断续，可在停车后对比“内置车机热点（5 GHz）”与当前 Wi-Fi Direct，或 USB；各播放约 10 分钟并导出带故障时间的新诊断。当前没有车机或 iPhone 的新实测，不承诺完全消除无线干扰。

## 安装

- 下载 `CarPlay-0.2.34-audio-test.apk`，这是主应用 `:mobile` 的**独立连接测试包**，包含从 SOLHK/CarPlay 旧公开预览包继承的实验性连接认证材料。
- 版本为 `0.2.34-hud-test`，versionCode 41，Android 7.0+。包名为 `com.solhk.carplay.hudtest`，使用本次测试签名；日志中的正式包为 `com.solhk.carplay`，因此两者并存，设置与配对不会自动迁移。此前若装过同包名、不同签名的源码测试包，Android 会拒绝覆盖。
- 先保留原应用，在停车后安装、选择自己的 iPhone，再测试连接、连续播放、切歌、导航播报和通话后音乐恢复。测试新包时请退出旧接收端，避免两个应用同时连接。
- 普通 CI 的 `CarPlay-source-only-debug` 仍不含认证材料，不能作为独立连接包。发布附件的 `audio-test.apk` 才是本次车机测试包。
- Android 签名密钥和连接认证源文件不进入 Git 或源码归档。运行输入的用途与限制见[第三方说明](THIRD_PARTY_NOTICES.md#experimental-authentication-data)。独立构建步骤见[构建指南](BUILD.md)。

## 验证

执行仓库要求的完整单元测试、Lint 和三个 Debug 应用构建；另执行带显式运行认证输入的 `:mobile:assembleStandaloneDebug`，检查 APK 包名、版本、签名、原生库和认证文件。新增回归覆盖 600/760 ms 间隙中不提前启动未满的音乐缓冲、短尾音最终播放、导航时延不增加，以及旧设置保留。实际结果记录在本次 GitHub 发布说明与随包测试报告中。
