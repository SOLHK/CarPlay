# CarPlay 0.2.36 — 音乐缓冲与导航延迟修复

主应用版本为 `0.2.36`，Android `versionCode=43`；独立 AAOS 应用同步为
`1.2.3` / `1203`。基于 0.2.35 的 `main` 提交
`23c22bef54dabf692a7dfc2a110fa6ff2419ccae`，保留既有包名、连接标识和用户设置。

## 已确认的问题与处理

### 增强音乐断流恢复时的额外积压

0.2.35 的增强缓冲音乐以最初投喂时刻计算进度。TCP 长时间无数据后，过去的
墙钟时间被当成应补送的音频，恢复时会连续投喂到约一秒的保护上限。
因此即使选择 100/150ms，恢复后的解码队列仍可能远大于所选预算。

新增真实本机 TCP、加密 RTP 和虚拟时钟回归，在未修复的代码上分别失败：

| 设置 | 恢复前已投喂 | 恢复后本应累计投喂 | 0.2.35 实际累计投喂 |
| --- | ---: | ---: | ---: |
| 有线 100ms | 7 帧 | 14 帧 | 54 帧 |
| 无线 150ms | 9 帧 | 18 帧 | 56 帧 |

测试格式是 48kHz AAC，每帧 1024 个采样；旧版恢复时新增的 47 帧约为 1003ms。
现在只在投喂确实落后超过一个帧/轮询周期时重新建立节拍，用硬件实际未播量
补足正常预载，不补偿断流期间的墙钟债务。正常连续供给仍采用原有时钟漂移
校正。尚未播放的音乐留在 TCP 预取库存中，不通过丢帧、加速播放来缩短队列。
没有硬件反馈时，估算位置保持单调，恢复的新帧不会立即被错误认定为已经听到。

### 无线导航、Siri 和通话的固定字节缓冲

0.2.35 只为有线非音乐音频取消了固定字节下限。无线仍有至少 16KiB 的容量和
4KiB 的应用启动量。8kHz 单声道 PCM16 下，这分别是 1024ms 和 256ms。

本版把非音乐音频改为按时长计算，软件容量预算不超过 100ms，应用启动目标为
20ms；设备要求的最低缓冲仍优先。原本已经更短的无线容量不被加长。
Android 12 以下的原生启动门槛可能仍接近音轨容量，不能把 20ms 当作实际首声延迟。

### 很短的提示音和音乐尾段卡在原生启动门槛

`AudioTrack.play()` 不保证低于原生门槛的 PCM 立即出声。Android 12 及以上在
短尾段等待到期、确有待播 PCM 且播放头停滞时，临时降低原生启动门槛。
只有本次硬件播放头实际移动后才恢复原门槛，覆盖第一条提示以及已经播过内容、
欠载后再次到来的短提示。平台拒绝或钳制请求时，保留实际门槛和播放位置，不
伪造音频已经输出，也不在每次维护轮询中重复请求。

Android 7–11 不支持同一原生门槛 API，本版不通过动态缩小再扩大设备缓冲冒险
实现相同功能；极短尾段仍受设备原生最低门槛约束。

### 导航焦点永久丢失后后续播报未重新申请

永久 `AUDIOFOCUS_LOSS` 会清理失效请求和释放计时器，下一条导航提示重新申请。
已放弃请求的延迟回调不能释放新请求；临时失焦保留正常恢复语义。不会在永久
失焦回调中立即抢回焦点。

### 比亚迪独立 HUD 输出的 250ms 轮询等待

有效转向、距离和路线结束消息到达现有输出工作线程后立即刷新。
原来的 250ms 周期任务保留作保活、状态过期检查和失败重试。
用户开关、诊断占用、重复数据去重、导航结束清理仍有效。
这里消除的是接收端等待下一次轮询的时间，广播和车机显示耗时仍需实测。

### 扬声器通话误用音乐策略及接收生命周期

- 扬声器通话可以继续使用媒体输出通道，但语音内容不再套用音乐预缓冲、
  音乐时钟变速和欠载后的暂停回填。普通音乐及 automotive compatibility 的
  音乐策略保留。
- UDP 音频拒绝重复监听和关闭后重新监听，绑定失败、绑定中关闭及回调重入
  都会清理套接字，避免重连后遗留旧接收线程和端口。
- 增强音乐停止输出先退休旧输出状态，重入的暂停/关闭不能递归停止旧输出
  或被外层旧控制操作覆盖。

## 延迟数值的准确含义

| 项目 | 本版目标或行为 |
| --- | --- |
| 普通无线音乐 | 保留 150ms 启动预缓冲选项与默认值 |
| 普通 USB 音乐 | 保留 100ms 默认启动预缓冲 |
| 增强缓冲音乐 | 100/150ms 基础预算，另有 20ms 轮询与 AAC 帧边界余量；设备原生门槛较大时优先保证能启动 |
| 导航和语音 | 应用启动目标 20ms，软件容量最多 100ms，受设备最低缓冲约束 |
| USB 地图画面 | 延续 0.2.35 的 100ms 接收端主动调度上限，不改变视频参考帧恢复机制 |
| 比亚迪独立 HUD | 状态更新无需等下一次 250ms 周期任务 |

以上是软件预算和逻辑修复，**不是实车端到端测量结果**。手机生成音频、无线
链路、车机 Android 音频 HAL、功放 DSP、视频解码和屏幕刷新都会增加总延迟。
较小缓冲不能覆盖更长的无线断流；300/500/1000ms 稳定性选项及已保存选择仍保留。

暂停恢复仍按 AAC 包处理；硬件停在一帧中间时，现有实现不提供解码后的逐采样
精确裁切，本版不宣称暂停/恢复达到逐采样无损。

## 验证与安装

需要执行仓库完整的单元测试、三个应用 Lint 和三个 Debug 构建，具体结果以本次
GitHub PR/CI 和交付记录为准。新增回归包含真实 TCP/UDP 生命周期、断流恢复、
RTP 回绕、暂停恢复库存、时钟漂移、原生启动门槛、连续短提示、音频焦点和即时
HUD 输出。

独立车测 APK 使用原有认证输入和签名，包名仍为 `com.solhk.carplay.hudtest`。
源码与 CI APK 继续不包含这些外部运行材料。安装后在关于页确认版本为 0.2.36；
若之前保存了更长音乐缓冲，在设置中选择无线 150ms / 有线 100ms 后重连。

停车状态下检查连续切歌、暂停/恢复、音乐叠加多条短导航播报、通话结束恢复、
HUD 转向与结束清理。声学延迟需用按键/提示触发时刻和实际扬声器输出作对比，
记录中位值、P95、断音及重复/缺失片段，不能从设置数字直接推断。
